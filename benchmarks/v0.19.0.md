# Benchmarks - v0.19.0

Date: 2026-07-05
Platform: macOS 26 (Apple Silicon, arm64; Darwin 25.4.0)
Rust: rustc 1.95.0 (59807616e 2026-04-14)
Command: `cargo bench`

Comparisons reference the last checked-in full release benchmark note, v0.18.0.
v0.19.0 is a maintenance release: one additive terminal-detection feature (Otty
support, #156) plus a dependency-maintenance batch that cleared the Dependabot
backlog and an AWS SDK security advisory (#157) — `shlex` 1→2, `sha2`
0.10→0.11 (RustCrypto digest 0.11 generation), `rquickjs` 0.10→0.12
(quickjs-ng to Unicode 17.0.0), `toml_edit` 0.22→0.25, and `aws-sdk-iam`
1.80→1.95 with its transitives. None of these touch a keystroke hot-path
algorithm: the fuzzy ranker (`nucleo`, unbumped) and the VT parser are
unchanged, so the expectation going in was flat-to-noise across every group,
with the only dependency-adjacent groups being `engine_suggest_sync_aws_sdk`
(aws-sdk), `engine_suggest_sync_token_only` (rquickjs/JS), the `alias_hit_*`
routes (shlex), and config-adjacent paths (toml_edit).

Gnuplot was not installed; Criterion used the plotters backend. Comparisons are
computed against the v0.18.0 report medians (cross-report, not a saved Criterion
baseline), so µs- and ns-scale rows carry normal run-to-run machine variance.

## Summary

`cargo bench` completed successfully. Every hot-path group is flat-to-noise
against v0.18.0, and the four dependency-adjacent groups are clean:

- **AWS SDK route** (`aws-sdk-iam` 1.80→1.95): `cold_iam_role_name_route`
  -1.79% (339.38 ms) and `warm_iam_role_name_route` -4.40% (1.2902 µs). The
  security bump did not regress the AWS dispatch path.
- **Token-only JS** (`rquickjs` 0.10→0.12, Unicode 17.0.0): the three fixtures
  v0.18.0 flagged as high-variance upticks to confirm **reverted hard** —
  `returns_tokens` -17.62%, `previous_token_branch` -20.10%, `regex_filter`
  -11.06% — exactly as that report predicted, and confirming the quickjs-ng
  engine bump carries no JS-path regression.
- **Alias routes** (`shlex` 1→2): `alias_hit_single` -2.56%, `alias_hit_multi`
  flat (-0.24%). The tokenizer major did not regress alias parsing.
- **Transforms / config-adjacent** (`toml_edit`): `transform_pipeline` is
  flat-to-better across the board (-1.3% to -2.4%).

The default keystroke path is unchanged: `fuzzy_ranking` is within ~1–2.5% of
v0.18.0, `vt_parse_throughput` is flat-to-better (-0.2% to -2.0%), and
`priority_sort` is essentially unchanged. No algorithmic regression on any
default code path.

Small upticks worth logging for next-release confirmation, all on benchmarks
v0.18.0 already documented as high-variance and none on a dependency-touched
path: `engine_suggest_sync/command_position` +7.69% (19.064 µs — the same
fixture that swung +13.40% then -9.50% over the last two reports),
`filesystem_fallback` +4.32% (ms-scale, fs-bound), `provider_route_systemd_units`
+16.08% (5.3746 µs — historically bounces between ~4.6 and ~5.7 µs),
`provider_route_dscl_users` +4.84%, `spec_loading` +1.99% (cold path), and
`memory/embedded_specs_heap_walk` +5.46% (embedded spec data is unchanged this
cycle; reads as heap-walk sampling variance). Every one is small-absolute or
inside its historical band.
