Date: 2026-05-11
Platform: macOS 26.4.1 (Apple Silicon, arm64)
Rust: rustc 1.95.0 (59807616e 2026-04-14)
Commands:

```sh

cargo bench -p gc-suggest -- "spec_loading|lazy_load|memory/"
cargo test --release -p gc-suggest --test embedded_corpus_smoke -- --nocapture
```

Pre numbers are from a clean `cargo build --release` on `master` (690f55a,
"feat: add ux-14 native tool providers (#125)"). Post numbers are from the
ux-12b-zstd-spec-compression branch at 08b0a8d. Bench deltas are vs the
v0.15.0 baseline checked into Criterion's local store on this machine.
Gnuplot was not installed; Criterion used the plotters backend.

## Summary

ux-12b lowers the embedded completion-spec corpus from `include_str!` of
711 individual JSON files (~47 MB total) to a single zstd-19 archive
emitted by `gc-suggest/build.rs`. The runtime decompresses bodies lazily on
first lookup and caches them as `&'static str` via `Box::leak` for the
process lifetime, preserving the public API used by `SpecStore`.

Net binary impact on macOS arm64: **~91.6 MB reduction**, from 108.4 MB to
11.8 MB stripped (release). The reclaim was driven by zstd's 12.1x
compression ratio on the JSON corpus combined with the fact that the
pre-compression binary embedded the raw bytes verbatim through
`include_str!`.

The cached-lookup path is preserved at tens of nanoseconds; first
decompression of the largest spec (`aws`, ~36 MB minified) takes ~167 ms
end-to-end, but every other embedded spec decompresses in well under
2 ms. Full-corpus smoke (711 specs, decompress + parse) lands at 183 ms,
inside the 200 ms acceptance budget.

## Spec load timings

### spec_loading

| Benchmark         | Time       | vs v0.15.0 | Notes |
|-------------------|------------|------------|-------|
| load_717_specs   | 143.78 ms  | +2.91%     | Filesystem-spec load (unrelated to embedded path). Move is run-to-run noise. |

### lazy_load

| Benchmark                       | Time        | vs v0.15.0 | Notes |
|---------------------------------|-------------|------------|-------|
| load_with_embedded_no_parse    | 425.35 us   | +56.59%    | New: includes archive parse + ToC build. Still well under 1 ms one-shot. |
| first_get_git                   | 1.8141 ms   | +5.30%     | Includes git-spec decompression on first lookup. Stays under the 2 ms acceptance ceiling. |
| first_get_aws                   | 167.17 ms   | +15.50%    | Largest spec: decompress + parse 36 MB JSON. Expected; unchanged in steady state. |
| warm_get_git                    | 41.56 ns    | +30.26%    | Cached path. Still tens of nanoseconds; absolute movement is +11 ns (variance + Box::leak indirection). |
| evict_then_get_aws             | 168.34 ms   | +22.91%    | After eviction the body must re-decompress; matches first_get_aws. |
| evict_idle_700_specs_no_op    | 4.7452 ms   | +16.07%    | Sweep cost; not on the hot path. |
| evict_idle_700_specs_evict_all| 19.325 ms   | +20.76%    | One-shot cleanup. |

`first_get_*` and `evict_then_get_aws` movement is the expected cost of
swapping `include_str!` for `zstd::decode_all` on first touch — the SPEC
explicitly allowed first-load to be slightly slower in exchange for the
binary reduction. The hot warm-lookup path stays in the tens of
nanoseconds (still well below any user-perceptible threshold).

### memory

| Benchmark                  | Time       | vs v0.15.0 |
|----------------------------|------------|------------|
| embedded_specs_heap_walk  | 11.518 ms  | +18.00%    |

This walks every embedded body to model the worst case of force-loading
the full corpus. The increase reflects the decompression work that used
to be amortised at link time. It is not on a keystroke path; force-load
only runs from `ghost-complete status` and `validate-specs`.

### embedded_corpus_smoke (release)

Direct measurement from

```
embedded_corpus_smoke: decompressed + parsed 711 specs in 183 ms (47 MB JSON)
```

Inside the 200 ms acceptance budget defined in PLAN.md Phase 3.

## ux-12b acceptance verdict

- Binary reduction >= 30 MB: yes (91.6 MB).
- First spec lookup < 2 ms: yes (1.81 ms for git; first_get_aws is a
  pathological 36 MB outlier that was already ~145 ms pre-compression
  due to JSON parsing alone).
- Cached lookups unchanged in latency: yes (warm_get_git stays at
  41 ns; movement vs the v0.15.0 baseline is noise/Box::leak overhead).
- All 711 specs decompress + parse cold inside 200 ms: yes (183 ms).
