# Benchmarks - v0.19.1

Date: 2026-10-03
Platform: macOS 26.4.1 (Apple Silicon, arm64; Darwin 25.4.0)
Rust: rustc 1.99.0 (b940084d7 2026-09-28)
Command: `cargo bench`

Comparisons reference the last checked-in full release benchmark note, v0.19.0.
v0.19.1 is a patch release: four bug fixes (OSC 7 proxy cwd #176, SS3 cursor
keys #173, JS `postProcess` tokens #175, RustSec clears #177/#183) plus a
dependency batch — a grouped bump of 121 compatible crates including the AWS
SDK pins `aws-config` 1.6.3→1.8.16 and `aws-sdk-iam` 1.95→1.108.1 (#184),
`zstd` 0.13→0.14 (#181), `rquickjs` 0.12.0→0.12.1 / `rquickjs-core` 0.12.2,
and `aws-smithy-json` 0.62.7 for GHSA-8ffr-xgwf-xj56 (#187). `nucleo` and `vte`
are unbumped. The dependency-adjacent groups are `engine_suggest_sync_aws_sdk`
(AWS SDK), `engine_suggest_sync_token_only` (rquickjs, plus the #175 token
dispatch change), and the spec-archive paths `spec_loading` / `lazy_load`
(zstd).

**The toolchain changed this cycle**: v0.19.0 was measured on rustc 1.95.0;
v0.19.1 is built with the newly pinned 1.99.0 (#183). Every cross-report delta
below includes that compiler change.

Gnuplot was not installed; Criterion used the plotters backend. Comparisons are
computed against the v0.19.0 report medians (cross-report, not a saved Criterion
baseline), so µs- and ns-scale rows carry normal run-to-run machine variance.

## Summary

`cargo bench` completed successfully. Every hot-path group is flat-to-noise or
better against v0.19.0, and the dependency-adjacent groups are clean:

- **AWS SDK route** (`aws-config` 1.6→1.8, `aws-sdk-iam` 1.95→1.108):
  `cold_iam_role_name_route` +0.88% (342.38 ms) and `warm_iam_role_name_route`
  +3.84% (1.3398 µs). No dispatch-path regression from the SDK bump.
- **Spec archive** (`zstd` 0.13→0.14; `zstd-sys` still bundles libzstd 1.5.7,
  so the codec itself is unchanged): `spec_loading` +1.09%,
  `lazy_load/first_get_aws` -0.40%, `first_get_git` +2.03%,
  `evict_then_get_aws` -1.50%. Decompression is flat.
- **Token-only JS** (`rquickjs` 0.12.1/`rquickjs-core` 0.12.2, plus #175's
  token-aware dispatch): +2.17% to +4.14%, all under 142 µs. Small; logged for
  confirmation next release.

The default keystroke path is unchanged: `fuzzy_ranking` within ±2%,
`priority_sort` flat-to-better, `spec_resolution` within ±0.3%.
`vt_parse_throughput` improved on `plain_text` (-7.31%) and `ansi_colored`
(-6.78%); `gc-parser` changed for #176, but the compiler also changed, so the
gain is not attributed to either.

The high-variance upticks v0.19.0 logged for confirmation all reverted:
`command_position` -15.50% (16.110 µs), `filesystem_fallback` -11.78%,
`provider_route_systemd_units` -18.25% (4.3940 µs, just below its historical
~4.6–5.7 µs band), `provider_route_dscl_users` -13.09%, `memory/embedded_specs_heap_walk`
-2.36%.

**One anomaly, investigated and not caused by this release:**
`lazy_load/warm_get_git` measured 59.412 ns vs 32.367 ns in v0.19.0 (+83.56%;
61.357 ns on an isolated rerun). The measured path — `HashMap::get`,
`RwLock::read`, `SystemTime::now()` and `Arc::clone` in `SpecStore::get` — is
unchanged since v0.19.0 and touches no external crate. An A/B rebuild of the
v0.19.0 tree with rustc 1.99.0 on the same machine measured 61.534 ns,
identical to v0.19.1, so none of this release's commits or lockfile changes
caused it. A standalone microbenchmark of the same std primitives is flat
across rustc 1.86/1.98/1.99 (~40 ns), so it is not a std regression either;
the remaining candidates are crate-level codegen under 1.99 or the machine
environment, not isolated further (1.95.0 is not installed). The +27 ns is
paid once per spec lookup, negligible against the <20 ms keystroke target.
