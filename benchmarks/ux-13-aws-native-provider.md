# UX-13 AWS Native Provider Benchmarks

Command:

```sh
cargo bench -p gc-suggest -- engine_suggest_sync_aws_sdk
```

The most recent run used:

```sh
cargo bench -p gc-suggest --bench suggest_bench engine_suggest_sync_aws_sdk -- --sample-size 10
```

Benchmarks:

- `engine_suggest_sync_aws_sdk/cold_iam_role_name_route`: loads the spec
  corpus, builds an SDK-enabled engine, and resolves the IAM `--role-name`
  completion route.
- `engine_suggest_sync_aws_sdk/warm_iam_role_name_route`: resolves the same
  route against an already-loaded engine and parsed AWS spec.

Results are generated by Criterion under
`target/criterion/engine_suggest_sync_aws_sdk/`. This benchmark measures sync
route resolution and provider scheduling; live AWS network latency is covered
by provider timeout tests and the SDK cache path.

Run on 2026-05-12:

| Benchmark | Median |
| --- | ---: |
| `cold_iam_role_name_route` | 336.50 ms |
| `warm_iam_role_name_route` | 1.3636 us |

The cold number includes loading the file-backed spec corpus and constructing
the engine. It is above the UX-13 target for SDK call latency, so follow-up
work should split first-AWS-spec parse cost from provider dispatch latency.
